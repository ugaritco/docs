<a name="introduction"></a>
## Introduction

Ugarit includes the ability to seed your database with data using seed classes. All seed classes are stored in the `database/seeders` directory. By default, a `DatabaseSeeder` class is defined for you. From this class, you may use the `call` method to run other seed classes, allowing you to control the seeding order.

> [!NOTE]
> [Mass assignment protection](/docs/{{version}}/eloquent#mass-assignment) is automatically disabled during database seeding.

<a name="writing-seeders"></a>
## Writing Seeders

To generate a seeder, execute the `make:seeder` [Scribe command](/docs/{{version}}/scribe). All seeders generated by the framework will be placed in the `database/seeders` directory (or the target artifact's `database/seeders` directory):

```shell
# Generate a standard seeder
php scribe make:seeder UserSeeder

# Generate a model-bound seeder (with factory instantiation)
php scribe make:seeder BranchSeeder --model=Branch

# Generate a seeder inside a modular domain artifact
php scribe make:seeder BranchSeeder --model=Branch --artifact=company
```

A model-bound seeder (also generated by `make:model --seed` or `--all`) calls the `seedModel` method of the base `Seeder`, which creates the fixed records of its `records()` method through the model's [factory](/docs/{{version}}/eloquent-factories), then the given number of random records (10 by default). The generated records are written from the model's fillable and translatable attributes, a translatable attribute given for every available locale; the factory fills the attributes a record omits, such as its foreign keys:

```php
public function run(): void
{
    // The fixed records, then 10 random ones (localized across active locales if translatable)
    $this->seedModel(Branch::class, 10);
}

protected function records(): array
{
    return [
        [
            'slug' => 'branch-1',
            'active' => true,
            'name' => ['en' => 'Name 1', 'ar' => 'Name 1'],
        ],
        [
            'slug' => 'branch-2',
            'active' => true,
            'name' => ['en' => 'Name 2', 'ar' => 'Name 2'],
        ],
    ];
}
```

A seeder class only contains one method by default: `run`. This method is called when the `db:seed` [Scribe command](/docs/{{version}}/scribe) is executed. Within the `run` method, you may insert data into your database however you wish. You may use the [query builder](/docs/{{version}}/queries) to manually insert data or you may use [Eloquent model factories](/docs/{{version}}/eloquent-factories).

As an example, let's modify the default `DatabaseSeeder` class and add a database insert statement to the `run` method:

```php
<?php

namespace Database\Seeders;

use Heritage\Database\Seeder;
use Heritage\Support\Facades\DB;
use Heritage\Support\Facades\Hash;
use Heritage\Support\Str;

class DatabaseSeeder extends Seeder
{
    /**
     * Run the database seeders.
     */
    public function run(): void
    {
        DB::table('users')->insert([
            'name' => Str::random(10),
            'email' => Str::random(10).'@example.com',
            'password' => Hash::make('password'),
        ]);
    }
}
```

> [!NOTE]
> You may type-hint any dependencies you need within the `run` method's signature. They will automatically be resolved via the Ugarit [service container](/docs/{{version}}/container).

<a name="using-model-factories"></a>
### Using Model Factories

Of course, manually specifying the attributes for each model seed is cumbersome. Instead, you can use [model factories](/docs/{{version}}/eloquent-factories) to conveniently generate large amounts of database records. First, review the [model factory documentation](/docs/{{version}}/eloquent-factories) to learn how to define your factories.

For example, let's create 50 users that each has one related post:

```php
use App\Models\User;

/**
 * Run the database seeders.
 */
public function run(): void
{
    User::factory()
        ->count(50)
        ->hasPosts(1)
        ->create();
}
```

<a name="calling-additional-seeders"></a>
### Calling Additional Seeders

Within the `DatabaseSeeder` class, you may use the `call` method to execute additional seed classes. Using the `call` method allows you to break up your database seeding into multiple files so that no single seeder class becomes too large. The `call` method accepts an array of seeder classes that should be executed:

```php
/**
 * Run the database seeders.
 */
public function run(): void
{
    $this->call([
        UserSeeder::class,
        PostSeeder::class,
        CommentSeeder::class,
    ]);
}
```

<a name="calling-artifact-seeders"></a>
### Autonomous Modular Artifact Seeding

Ugarit provides out-of-the-box autonomous discovery for modular domain artifacts. Instead of manually maintaining an orchestrator array of every artifact seeder, you may invoke `$this->callArtifactSeeders()` inside your `DatabaseSeeder`:

```php
namespace Database\Seeders;

use Heritage\Database\Seeder;

class DatabaseSeeder extends Seeder
{
    /**
     * Seed the application's database.
     */
    public function run(): void
    {
        // Automatically discovers and runs all modular artifact seeders in topological priority order
        $this->callArtifactSeeders();
    }
}
```

The discovery engine intelligently executes foundational seeders first (`i18n`, `geography`, `identity`), followed by domain artifacts in alphabetical order.

<a name="muting-model-events"></a>
### Muting Model Events

While running seeds, you may want to prevent models from dispatching events. You may achieve this using the `WithoutModelEvents` trait. When used, the `WithoutModelEvents` trait ensures no model events are dispatched, even if additional seed classes are executed via the `call` method:

```php
<?php

namespace Database\Seeders;

use Heritage\Database\Seeder;
use Heritage\Database\Console\Seeds\WithoutModelEvents;

class DatabaseSeeder extends Seeder
{
    use WithoutModelEvents;

    /**
     * Run the database seeders.
     */
    public function run(): void
    {
        $this->callArtifactSeeders();
    }
}
```

<a name="running-seeders"></a>
## Running Seeders

You may execute the `db:seed` Scribe command to seed your database. By default, the `db:seed` command runs the `Database\Seeders\DatabaseSeeder` class, which may in turn invoke other seed classes. However, you may use the `--class` or `--artifact` options to specify a specific seeder or modular artifact to run individually:

```shell
# Run the main DatabaseSeeder (and all discovered artifact seeders)
php scribe db:seed

# Run a specific seeder class
php scribe db:seed --class=UserSeeder

# Run all seeders belonging to a specific modular artifact
php scribe db:seed --artifact=company
```

You may also seed your database using the `migrate:fresh` command in combination with the `--seed` option, which will drop all tables and re-run all of your migrations. This command is useful for completely re-building your database. The `--seeder` option may be used to specify a specific seeder to run:

```shell
php scribe migrate:fresh --seed

php scribe migrate:fresh --seed --seeder=UserSeeder
```

<a name="forcing-seeding-production"></a>
#### Forcing Seeders to Run in Production

Some seeding operations may cause you to alter or lose data. In order to protect you from running seeding commands against your production database, you will be prompted for confirmation before the seeders are executed in the `production` environment. To force the seeders to run without a prompt, use the `--force` flag:

```shell
php scribe db:seed --force
```
